# Your Profile

Your GitHub profile is a portfolio. Recruiters, apprenticeship trainers and clients look at it; make the first 10 seconds count.

## The basics
- **Name, photo, one-line bio** ("Software developer · Java/Kotlin · building websites for small businesses").
- **Location, website, links** (LinkedIn, your site).
- **Pinned repositories** (up to 6): your best work, not your first tutorial. Each with a description, topics and a README with a screenshot.

## Profile README
Create a **public repository with your exact username** (e.g. `ada/ada`). Its `README.md` appears at the top of your profile:
```markdown
# Hi, I'm Ada 👋

Software developer from Bavaria, starting my apprenticeship as a
Fachinformatiker für Anwendungsentwicklung.

- 🔭 Currently building a self-hosted wiki engine in Kotlin
- 🌐 Websites for small businesses: https://example.com
- 🛠️ Java · Kotlin · TypeScript · Next.js · Git

### Selected projects
| Project | What |
|---|---|
| [wiki-engine](https://github.com/ada/wiki-engine) | Kotlin wiki with compressed history and typo-tolerant search |
| [shop](https://github.com/ada/shop) | Next.js shop with Stripe checkout |
```
Keep it short and current. Skip long lists of every technology you've heard of.

## What makes a repository look good
| | |
|---|---|
| README | what, why, screenshot, how to run ([[github/Repository Essentials]]) |
| Green CI badge | shows you test ([[github/GitHub Actions]]) |
| Clean history | meaningful commit messages ([[git/Commit Messages]]) |
| Issues and PRs | even on solo projects, they show how you work |
| Live demo | Pages or your own server ([[github/Releases and Pages]]) |
| License | MIT for open portfolio code |

## The contribution graph
The green squares count commits on the default branch, PRs, issues and reviews. It's nice, not important. Don't game it; a few substantial projects beat daily typo commits. Private repository contributions can be shown anonymously (*Contribution settings*).

## Private vs public work
Client work usually stays private. You can still:
- describe it in the profile README (without confidential details),
- publish a small, anonymised open-source part (a component, a tool you built),
- write about it on your site.

## Achievements, Sponsors, Stars
Badges like *Pull Shark* appear automatically. **Stars** are bookmarks (and a popularity signal); **GitHub Sponsors** lets people fund your open-source work.
