# Glossary

GitHub words, in one place.

| Term | Meaning |
|---|---|
| **repository** (repo) | a project on GitHub: code, history, issues, PRs and settings |
| **fork** | your own copy of someone else's repository under your account ([[github/Forks and Cloning]]) |
| **clone** | a local copy of a repository on your machine |
| **upstream** | the original repository a fork came from |
| **pull request** (PR) | a proposal to merge one branch into another, with review and checks ([[github/Pull Requests]]) |
| **draft PR** | a PR marked as not ready for review yet |
| **review** | comments plus a verdict: comment, approve or request changes ([[github/Code Review]]) |
| **suggestion** | a review comment containing replacement code the author can apply with one click |
| **status check** | a pass/fail result reported on a commit, usually from Actions |
| **squash and merge** | merge a PR as one single commit |
| **merge queue** | a queue that tests PRs together before merging them ([[github/Protecting Main]]) |
| **issue** | a tracked bug, task or idea with a discussion thread ([[github/Issues and Projects]]) |
| **label** | a tag used to categorise issues and PRs |
| **milestone** | a group of issues and PRs targeting a release or date |
| **Project** | a board or table view that tracks issues and PRs across repositories |
| **Discussions** | a forum for questions and ideas inside a repository |
| **Actions** | GitHub's built-in CI/CD that runs workflows on events ([[github/GitHub Actions]]) |
| **workflow** | a YAML file in `.github/workflows/` describing an automated process |
| **job** / **step** | a unit of work on one runner / one command or action inside it |
| **runner** | the machine that executes a workflow job |
| **action** | a reusable step, e.g. `actions/checkout` |
| **artifact** | files uploaded by a workflow run |
| **secret** | an encrypted value available to workflows, hidden from logs ([[github/Secrets and Environments]]) |
| **variable** | non-secret configuration for workflows (`vars.X`) |
| **environment** | a deploy target with its own secrets and protection rules |
| **GITHUB_TOKEN** | the automatic, short-lived token every workflow run gets |
| **OIDC** | token exchange that lets workflows log into clouds without stored keys |
| **ruleset** | rules that protect branches or tags, like required reviews |
| **CODEOWNERS** | a file mapping paths to the people or teams who must review them |
| **release** | a tagged version with notes and optional downloadable files ([[github/Releases and Pages]]) |
| **Pages** | free static-site hosting straight from a repository |
| **Packages** / **ghcr.io** | GitHub's package and container registry ([[github/Packages]]) |
| **Dependabot** | automated dependency vulnerability alerts and update PRs ([[github/Security]]) |
| **secret scanning** / **push protection** | detects / blocks committed credentials |
| **CodeQL** | GitHub's code analysis engine for security bugs |
| **organization** | a shared account for a company or group, with teams ([[github/Organizations and Permissions]]) |
| **outside collaborator** | someone with access to specific repositories of an organization without being a member |
| **deploy key** | an SSH key with access to one repository |
| **personal access token** (PAT) | a password-like token for scripts and tools |
| **gh** | the official GitHub command-line tool ([[github/GitHub CLI]]) |
| **github.dev** | the web editor that opens when you press `.` |
| **Copilot** | GitHub's AI assistant for code completion, chat, review and agents ([[ai-prompting/Coding Agents]]) |
